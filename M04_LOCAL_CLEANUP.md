# Проверка локальной уборки временных видео

Команда `npm run video:staging:clean:local` предназначена только для отдельной тестовой SQLite и локальных файлов внутри `.test-data`. Она не подключается к Neon, не читает `.env`, не создаёт базу и не применяет миграции. Рабочий сайт и production этой командой обслуживать нельзя.

В отдельном терминале укажите уже существующие пути своей тестовой базы (с таблицей direct_video_uploads) и каталога видео:

```powershell
$env:DATABASE_DRIVER = 'sqlite'
$env:STORAGE_DRIVER = 'local'
$env:DATABASE_URL = ''
$env:DATABASE_PATH = '.test-data/my-check/test.sqlite'
$env:VIDEO_DIR = '.test-data/my-check/videos'
npm run video:staging:clean:local -- --cycles=2 --interval-ms=1000 --batch=25 --max-batches=100
```

Пути выше — пример, команда их не создаёт. Уборка откажется при DATABASE_URL, другом драйвере, отсутствующем файле, пути вне `.test-data` или ссылке/junction, ведущей наружу. Пути проверяются после разрешения файловых ссылок. Не подставляйте рабочую БД и реальные документы.

Каждый цикл начинает обход заново: так подбираются поздние файлы после отмены/истечения подписи. По умолчанию один цикл, максимум 10; интервал 100–60000 мс, размер пакета 1–100, максимум пакетов за цикл 1–1000. Это конечный запуск, а не установленная фоновая служба. Во время обычной работы приложения команда автоматически не запускается.

Вывод — JSON со счётчиками cycle, checked, deleteConfirmed, failed, incomplete. deleteConfirmed означает подтверждённую идемпотентную операцию удаления, включая уже отсутствующий объект. Код выхода 1 означает отказ конфигурации, ошибку удаления или незавершённый ограниченный обход. Если incomplete=true, полного обхода не было: повторите с подходящим лимитом. Успех не означает отзыв старой подписи или отсутствие будущей поздней отправки; журнал сохраняется для следующих циклов.

Проверки команды используют отдельную SQLite: повторное появление файла между двумя циклами, сохранность журнала, запрет production/выхода за каталог/junction, лимиты, неполный обход и отсутствие секретов в сообщении об отказе. Реальное поведение S3, расписание и безопасный конечный срок хранения журнала остаются отдельными незавершёнными задачами M04.
